## Context

参见 `proposal.md` 的动机。项目是 Java 21 单模块 Gradle 工程，已经直接依赖 Apache HttpClient 5.6.4 和 Jackson 3.2.2，当前没有 Spring Boot Web 层。现有 JSON 序列化器服务于 RPC 并将错误映射为 RPC 异常，因此 HTTP 能力不应复用其异常语义。

本设计需要同时处理 TLS 安全边界、连接资源生命周期、请求体资源关闭、泛型 JSON 类型保留以及客户端级与请求级超时优先级。

## Goals / Non-Goals

**Goals:**

- 提供线程安全、共享连接资源且可通过静态方法直接调用的同步 HTTP 客户端封装。
- 通过一套请求模型统一方法、URL 文本、请求头、查询参数、请求体和单次超时。
- 在保持原始响应诊断信息的同时提供 JSON 直接转换重载。
- 让安全默认值、分阶段超时和默认 JSON 映射规则在类型与测试中明确表达。

**Non-Goals:**

- 不提供异步、响应式、重试、重定向策略定制、代理、认证、Cookie 管理或文件下载流式 API。
- 不将客户端注册为 Spring Bean，也不新增 Controller。
- 不承诺一个覆盖 DNS 到完整响应读取全过程的绝对墙钟总时限；配置分别约束连接池获取、连接建立和响应等待阶段。
- 不提供单次请求跳过 SSL 校验；TLS 策略属于客户端连接池级配置，避免在共享连接中产生请求级安全语义歧义。

## Decisions

### 1. 使用静态 `HttpClients` 门面管理进程级共享客户端

`org.example.simple.http.HttpClients` 设计为不可实例化的静态工具类。`get`、`post`、`put`、`delete`、`execute` 和 `executeJson` 均为静态方法，内部共享一个 Apache `CloseableHttpClient` 和对应 `ObjectMapper`。首次请求按需创建使用安全默认配置的共享客户端；调用方无需保存实例或使用 try-with-resources。

`configure(HttpClientConfig)` 用于设置进程级全局配置，`shutdown()` 用于幂等关闭共享连接池。内部使用公平读写锁：每次请求在完整执行期间持有读锁，配置替换或关闭持有写锁，因此旧连接池不会在请求执行中途关闭。配置替换先验证并创建新客户端，再交换引用并关闭旧客户端；关闭后请求返回客户端状态异常，调用 `configure` 可重新启用。该取舍引入受控全局状态，但符合静态直接调用目标，并通过测试重置默认配置保持隔离。

### 2. 使用不可变请求对象统一方法重载

新增不可变请求模型和构建器，字段包括方法、URL 文本、查询参数、请求头、可选请求体及可选单次超时。`HttpRequestData.get`、`post`、`put`、`delete` 以及 `HttpClients` 的同名静态入口均直接接收 `String url`，调用方式形如 `HttpClients.get("http://127.0.0.1:23456/hello")`，不向调用方暴露客户端构造或 `URI` 参数。构建请求时校验 URL 文本，执行层再将其解析为内部 `URI` 并追加查询参数，最终汇聚到一个执行路径。请求体使用受控的封闭类型表达 JSON、URL 编码表单、multipart 和文件二进制，避免用 `Object` 加内容类型字符串做运行时猜测。

multipart 文本部分使用 UTF-8；文件部分由路径、字段名、可选文件名和媒体类型组成。二进制请求采用 `Path`，执行时由 Apache 实体读取，客户端负责在响应完成或失败后释放相关资源。GET 明确禁止请求体；其他三种方法允许请求体，以覆盖带 body 的 DELETE 服务。

不保留公开 `URI` 重载，避免调用方仍需选择参数形式并确保主要 API 始终易用。也不采用为每种方法和内容类型组合大量静态重载的方案，因为接口数量会快速膨胀且难以加入请求级配置。

### 3. 分离原始响应与 JSON 转换

执行层先生成不可变 `HttpResponseData`，包含状态码、不可变响应头和非空响应字节。`execute` 返回原始响应；`executeJson` 分别接受 `Class<T>` 与 Jackson `TypeReference<T>`，以支持普通和泛型目标类型。

仅 `2xx` 被视为成功。非 `2xx` 抛出 `HttpClientException` 并携带原始响应；参数、超时、传输和 JSON 转换通过异常类别或错误码区分，异常消息使用中文并保留底层原因。响应体在返回或抛错前完整读取，底层 response 使用 try-with-resources 关闭。

选择字节数组而不是只暴露字符串，可正确保留二进制响应和服务端原始诊断内容。流式大响应不在本次范围内。

### 4. 分离连接超时和请求超时

`HttpClientConfig` 分别要求正数、有限的连接超时和请求超时，`defaults()` 将两者均初始化为 5 秒。连接超时仅约束建立 TCP 连接的阶段；请求超时约束从连接池获取连接和等待响应的阶段。请求对象保留可选的单次请求超时，执行时先选择请求级值，否则使用静态全局请求超时；单次覆盖只附着于当前 Apache request，不修改共享默认对象，也不改变全局连接超时。

分离两个值可避免慢连接建立与慢服务响应相互挤占配置语义，同时保持单次调用只覆盖请求阶段的简单接口。构造器和构建器均校验两个值非空、大于零且不超出底层客户端可表达范围。

### 5. SSL 跳过校验只能显式在客户端级启用

默认使用 JVM 信任库和标准主机名校验。`skipSslVerification=true` 时，为静态共享客户端构建信任所有证书的 TLS 上下文并配置无操作主机名校验器。该配置影响后续全部静态 HTTPS 请求，并在 Javadoc 中标注仅适合受控测试或内网场景。

不自动回退到不安全 TLS，也不允许单次请求切换，因为连接复用使请求级 TLS 策略无法可靠映射到既有连接。

### 6. 初始化并隔离 HTTP 默认 JSON 配置

HTTP 客户端持有调用方可注入的 Jackson `ObjectMapper`。默认映射器不使用裸构造结果，而是在 `HttpClientConfig.defaults()` 和构建器默认值中通过同一工厂完成初始化：关闭未知字段反序列化失败，序列化时省略值为 `null` 的属性，并启用 Java 时间类型支持且关闭时间戳输出，使日期时间使用 ISO-8601 字符串。显式 JSON `null` 反序列化仍按 Jackson 常规语义映射为 Java `null`。调用方显式注入映射器时完整保留其自定义行为，不对其二次修改。

Jackson 3.2.2 的 `jackson-databind` 已包含 Java 时间支持，因此不新增时间模块依赖。该隔离配置不会让 RPC 的日期格式和 `RpcException` 语义渗入通用 HTTP 层。实现前核对 multipart builder 所需类是否已由 `httpclient5` 提供；仅在编译证明缺失时增加 `httpcore5` 等最小依赖，不预先添加重复依赖。

## Risks / Trade-offs

- [跳过 SSL 校验会使连接易受中间人攻击] → 默认关闭，只能在客户端创建时显式启用，并在 API 文档中突出安全警告。
- [完整缓冲响应可能造成大响应内存压力] → 本次定位为普通工具调用并记录限制；未来以独立变更增加最大响应限制或流式 API。
- [`HttpClients` 与 Apache 同名类容易导入混淆] → 对外包名清晰，内部对 Apache 工厂类使用全限定名或避免同名 import。
- [静态全局状态可能导致测试之间相互影响] → 提供显式 `configure` 和 `shutdown`，测试在前后恢复默认配置并禁止并行修改全局配置。
- [配置替换可能与正在执行的请求竞争] → 使用公平读写锁覆盖完整请求生命周期，写操作等待读操作结束后再交换和关闭客户端。
- [分阶段超时不等于绝对总时限] → 文档明确连接超时与请求超时的阶段语义，并使用可控慢服务验证响应超时和覆盖优先级。
- [忽略未知字段可能掩盖服务端字段拼写变化] → 该行为仅用于提高 HTTP 响应兼容性，测试固定其语义；严格场景可注入自定义映射器。
- [文件在请求构造后、执行前可能被删除或失去权限] → 在执行时检查可读性并将失败映射为参数或传输异常，测试覆盖不存在文件。
- [带请求体的 DELETE 并非所有服务端都支持] → 客户端按 HTTP 语义允许发送，不对远端兼容性作保证。

## Migration Plan

1. 新增 HTTP 包内的配置、请求体、请求、响应、异常和客户端类型，不改动现有 RPC 包。
2. 使用本地测试 HTTP/HTTPS 服务验证编码、状态处理、JSON 转换、TLS 与超时。
3. 运行全部测试与构建后供调用方逐步引入；现有功能无需迁移。
4. 如需回滚，删除新增 HTTP 包和测试；只有在实际新增依赖时再同步移除该依赖。
