## Why

当前用户列表点击“新增用户”后会跳转到独立的 `/users/new` 表单页。新增用户属于字段较少、提交后仍需继续查看列表的轻量操作，页面跳转会打断列表上下文，也增加了用户返回列表的操作成本。

因此，将新增用户改为在用户列表页内通过弹出窗口完成，让用户在不离开列表的情况下录入并提交新用户。

## What Changes

- 用户列表页点击“新增用户”时，不再跳转 `/users/new`，改为打开 Element Plus 对话框。
- 对话框内保留现有新增用户字段与基础校验：账号、姓名、手机号、邮箱。
- 新增成功后关闭对话框、提示“已生效”或“已提交审批”，并刷新用户列表。
- 新增失败时保留对话框和已填写内容，供用户修改后重新提交。
- 关闭对话框后清空表单与校验状态，下次打开时展示干净表单。
- 编辑用户仍沿用 `/users/:id/edit` 独立页面，不改变编辑流程。
- 移除不再使用的 `/users/new` 新增页面路由；新增功能不改变任何后端接口、请求字段或审批逻辑。

## Capabilities

### Modified Capabilities

- `identity/user-management`: 用户新增的前端交互由独立页面切换为用户列表页内的弹出窗口，后端业务行为与审批状态保持不变。

## Impact

- 影响范围仅为 `fronted/` 与本变更的 OpenSpec 文档。
- 主要修改 `src/views/UserListView.vue`、`src/views/UserFormView.vue` 与 `src/router/index.ts`；可按职责拆出新增用户弹窗组件。
- 不修改 `backend/`，不新增依赖，不改变现有 API 契约。
