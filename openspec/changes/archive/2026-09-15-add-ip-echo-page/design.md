## Context

本项目没有前端框架、静态资源托管或可用的 IP 回显接口。纯浏览器 JavaScript 不可信地获取 HTTP 连接的远端地址，因此需要一个同源服务端。参见 `proposal.md` 的动机。

## Goals / Non-Goals

**Goals:**

- 以仅使用 Node.js 内置模块的服务端回显访问者 IP。
- 以单文件原生 HTML、CSS 和 JavaScript 提供可访问、可复制、可刷新的页面。
- 在窄屏与键盘操作时保持可用性，并对减少动效偏好做出响应。

**Non-Goals:**

- 不查询归属地、运营商、地理位置或代理信誉。
- 不引入 Node.js 依赖、包管理文件或前端框架。
- 不将任意 `X-Forwarded-For` 请求头视为可信的 IP 来源。

## Decisions

### 1. 使用同源 Node.js 回显接口

在仓库根目录新增 `echo-ip-server.js`，使用 `node:http`、`node:fs`
和 `node:path` 托管 `echoIp.html`。`GET /api/ip` 仅根据 `req.socket.remoteAddress`
返回 JSON，以避免未知代理传入伪造的转发头。

端口由 `PORT` 环境变量覆盖，未设置时使用 `3000`。连接地址以 `::ffff:` 开头时去除前缀。
比起依赖公共 IP 查询服务，该方案不暴露访问者数据、不依赖 CORS，也可在内网中测试。

### 2. 以网络探针为页面视觉方向

页面服务于需要快速确认网络出口的开发者。视觉标记是一个仿终端探针面板：
深蓝黑背景、湖蓝状态小点和等宽的 IP 读数。签名元素是 IP 位于一条渐变“信号轨道”之上，即使不读文字也能感知页面正在检测网络。

调色以 `#07131f`（深海）、`#0e2638`（面板）、`#4de4c1`（信号）、
`#f5fbff`（读数）、`#9eb3c4`（说明）和 `#ffb86b`（错误）为核心色。字体优先使用系统等宽字体显示 IP，正文使用系统无衬线字体。

```
+-----------------------------------------+
| 网络探针                    在线 ●      |
|                                         |
| 你的请求地址                            |
| ═══════ 203.0.113.42 ═══════            |
|                                         |
| [复制地址]              [重新检测]      |
| 结果来自当前连接，不会发送给第三方。     |
+-----------------------------------------+
```

加载时只让信号小点轻微脉冲；尊重减少动效偏好时关闭动画。这比通用的卡片和突出的大数字更贴近页面的网络诊断语境。

### 3. 使用渐进增强的原生交互

页面加载后立即调用 `fetch('/api/ip')`。在请求期间显示加载状态，
请求失败时使用语义清晰的错误文字与重试控件。复制优先使用
`navigator.clipboard.writeText` ，在不可用时提示访问者手动复制，不使用已过时的剪贴板 API。

## Risks / Trade-offs

- [服务端看到的地址可能是反向代理地址] → 页面说明结果来自当前连接；生产代理信任策略应在部署层明确配置。
- [Clipboard API 需要安全上下文] → 剪贴失败时明确告知访问者可选中地址手动复制。
- [端口被占用] → 支持 `PORT` 环境变量覆盖，并在启动失败时输出明确错误。

## Migration Plan

1. 添加页面与 Node.js 服务脚本。
2. 使用 Node.js 启动服务并访问 `http://127.0.0.1:3000/echoIp.html`。
3. 验证页面加载、IP 查询、复制、刷新和未知路径的错误返回。
4. 回滚时删除新增的页面和服务脚本即可，不影响现有 Java 运行方式。
