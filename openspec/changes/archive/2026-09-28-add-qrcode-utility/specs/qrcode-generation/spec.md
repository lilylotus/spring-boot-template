# Spec Delta

## Purpose

为 Java 应用提供统一的二维码生成与解码入口：把一段文本编码为 PNG 二维码，并以 Base64 字符串、data URI、指定文件或调用方输出流四种形态交付，支持在码图中间叠加提示文本；反向支持把 Base64/data URI、输入流或文件形式的二维码 PNG 解码回原始文本。明确选项默认值、参数校验、异常分类与资源所有权。

## ADDED Requirements

### Requirement: 文本到 PNG 二维码的统一入口
系统 SHALL 提供静态工具入口，接收待编码文本和可选生成选项，输出 QR_CODE 码制的 PNG 图片。系统 MUST 支持四种输出形态：标准 Base64 文本、`data:image/png;base64,` 前缀的 data URI、指定文件路径、调用方提供的输出流。未传入选项的重载 MUST 等价于传入默认选项。四种形态 MUST 使用同一条编码与渲染管线，对相同文本和相同选项产生相同的图片内容。

#### Scenario: 生成 Base64 PNG
- **WHEN** 调用方传入非空文本并请求 Base64 输出
- **THEN** 系统返回可由标准 Base64 解码器还原的字符串，解码后的字节是一张 PNG 图片，且该图片可被二维码解码器识别为原始文本

#### Scenario: 生成 data URI
- **WHEN** 调用方传入非空文本并请求 data URI 输出
- **THEN** 系统返回以 `data:image/png;base64,` 开头的字符串，去掉该前缀后的内容与 Base64 输出一致

#### Scenario: 中文与链接文本往返
- **WHEN** 待编码文本为中文字符串或包含查询参数的 URL
- **THEN** 生成的图片解码后与原始文本完全一致，不出现字符集导致的乱码

#### Scenario: 输出形态之间内容一致
- **WHEN** 调用方以相同文本和相同选项分别请求 Base64、文件和输出流三种形态
- **THEN** 三者得到的 PNG 字节内容相同

### Requirement: 生成选项与默认值
系统 SHALL 提供不可变的生成选项类型，覆盖图片边长、静区宽度、纠错等级、字符集、前景色和背景色，并 MUST 为每个选项提供可直接使用的默认值：边长 300 像素、静区 1 个模块、纠错等级中等、字符集 UTF-8、前景色不透明黑、背景色不透明白。静区宽度的单位 MUST 是模块数而不是像素。纠错等级 MUST 通过工具自有的枚举暴露，不得要求调用方依赖第三方库类型。系统 MUST 拒绝越界的边长和静区取值，并 MUST 支持带透明通道的背景色。

#### Scenario: 使用默认选项
- **WHEN** 调用方使用不接收选项的重载
- **THEN** 系统按默认边长、静区、纠错等级、字符集和颜色生成图片，无需调用方提供任何配置

#### Scenario: 自定义边长与纠错等级
- **WHEN** 调用方指定更大的边长和更高的纠错等级
- **THEN** 输出图片的宽高相等且不小于请求的边长，图片仍可解码为原始文本

#### Scenario: 自定义颜色与透明背景
- **WHEN** 调用方指定自定义前景色和带透明通道的背景色
- **THEN** 输出 PNG 保留透明通道，图片仍可解码为原始文本

#### Scenario: 拒绝越界选项
- **WHEN** 调用方指定小于最小可用模块边长或超过上限的边长，或指定负数静区
- **THEN** 系统在构建选项时抛出带中文描述的参数异常，不生成图片

### Requirement: 中间提示文本叠加
系统 SHALL 支持通过选项配置在二维码中间叠加提示文本，可配置项 MUST 包含文本内容、字体名称、字号、文字颜色、背板颜色和背板占图片边长的比例，并 MUST 为除文本内容外的每项提供默认值。未配置提示文本时，输出 MUST 与不具备该能力时完全一致。配置提示文本时，系统 MUST 先在中间绘制背板再绘制文字，背板边界 MUST 对齐到模块边界，且叠加后的图片 MUST 仍能被二维码解码器解出原始文本。提示文本 MUST 支持以换行符显式分行，且 MUST 居中绘制。字号未显式指定时，系统 MUST 自动适配到能完整放入背板的最大字号；显式指定的字号 MUST NOT 被自动缩放。系统 MUST 拒绝提示文本与低纠错等级的组合，MUST 拒绝无法放入背板的提示文本，并 MUST 在提示文本包含当前字体无法显示的字符时以专门的错误类别失败，而不是输出缺字图片。

#### Scenario: 不配置提示文本
- **WHEN** 调用方未配置提示文本
- **THEN** 输出图片中间不出现任何叠加内容，字节内容与不具备叠加能力时一致

#### Scenario: 叠加后仍可识别
- **WHEN** 调用方配置提示文本并使用默认背板占比
- **THEN** 输出图片中间出现居中的背板与文字，且该图片解码后仍得到原始编码文本

#### Scenario: 多行提示文本
- **WHEN** 提示文本包含换行符
- **THEN** 系统按换行符分行、整体居中绘制，不做自动换行，且图片仍可解码为原始文本

#### Scenario: 字号自动适配
- **WHEN** 调用方未指定字号且提示文本较长
- **THEN** 系统自动选用能完整放入背板的最大字号，文字不越出背板范围

#### Scenario: 拒绝放不下的提示文本
- **WHEN** 显式指定的字号使文本超出背板，或自动适配到最小字号仍无法放入
- **THEN** 系统抛出带中文描述的参数异常，不输出文字溢出到模块区域的图片

#### Scenario: 拒绝低纠错等级下的叠加
- **WHEN** 调用方在配置提示文本的同时把纠错等级设为最低等级
- **THEN** 系统在构建选项时抛出带中文描述的参数异常，并在消息中给出建议的纠错等级

#### Scenario: 字体缺字快速失败
- **WHEN** 提示文本包含当前字体无法显示的字符
- **THEN** 系统抛出标注为字体类别的工具异常，消息包含字体名与首个无法显示字符的位置，且不输出缺字图片

### Requirement: 参数校验与失败语义
系统 MUST 在编码前校验入参，对 `null` 文本、空文本以及 `null` 的目标文件、输出流或选项抛出带中文描述的参数异常；对 `null` 的解码输入来源（Base64/data URI 文本、输入流、文件）同样抛出带中文描述的参数异常，Base64 文本格式本身不合法时也 MUST 抛出参数异常。纯空白文本 MUST 视为合法内容。文本超出所选纠错等级的最大容量或无法按所选字符集编码时，系统 MUST 抛出标注为编码类别的工具异常；提示文本无法由当前字体显示时 MUST 抛出标注为字体类别的工具异常；待解码内容不是可识别的图片、或图片中未找到可识别的二维码、或找到但内容无法通过校验时，MUST 抛出标注为解码类别的工具异常；读写失败时 MUST 抛出标注为输出类别的工具异常。工具异常携带的错误类别 MUST 足以区分这四类失败。工具异常 MUST 保留底层原因，MUST 使用中文说明，且 MUST NOT 在消息中包含完整的待编码文本或图片字节。系统 MUST NOT 自行记录日志。

#### Scenario: 拒绝空输入
- **WHEN** 待编码文本为 `null` 或空字符串，或目标文件、输出流、选项为 `null`
- **THEN** 系统抛出带中文描述的参数异常，不产生任何输出

#### Scenario: 接受纯空白文本
- **WHEN** 待编码文本仅包含空白字符
- **THEN** 系统正常生成图片，解码结果与原始空白文本一致

#### Scenario: 文本超出容量
- **WHEN** 待编码文本长度超过所选纠错等级下二维码的最大容量
- **THEN** 系统抛出标注为编码类别的工具异常，保留底层原因，且消息中不包含完整文本

#### Scenario: 区分编码失败与写出失败
- **WHEN** 调用方分别遇到文本无法编码和目标流写出中断两种失败
- **THEN** 两次异常携带不同的错误类别，调用方可据此分支处理而无需解析消息文本

#### Scenario: 拒绝空的解码输入
- **WHEN** 解码入口的 Base64/data URI 文本、输入流或文件参数为 `null`，或 Base64 文本为空字符串或格式非法
- **THEN** 系统抛出带中文描述的参数异常，不返回任何解码结果

### Requirement: 文件写出与流所有权
写入指定文件时，系统 MUST 在父目录不存在时创建父目录，MUST 覆盖同名文件，并 MUST 保证失败时不在目标路径留下不完整的图片文件，也不遗留自身创建的临时文件。写入调用方提供的输出流时，系统 MUST NOT 关闭该流；写出中途失败时输出流可能已包含不完整字节。系统 MUST NOT 持有跨调用的可变状态，选项对象 MUST 可安全地跨线程共享。

#### Scenario: 写入不存在的目录
- **WHEN** 目标文件位于尚不存在的目录下
- **THEN** 系统创建所需父目录并写出完整的 PNG 文件

#### Scenario: 覆盖同名文件
- **WHEN** 目标路径已存在文件
- **THEN** 系统用新生成的 PNG 覆盖原文件，覆盖后文件可被解码为本次的文本

#### Scenario: 写出失败不留残缺文件
- **WHEN** 写出过程中发生失败
- **THEN** 目标路径保持为原有内容或不存在，不出现无法解码的残缺文件，且不遗留临时文件

#### Scenario: 不关闭调用方输出流
- **WHEN** 调用方传入自己管理的输出流
- **THEN** 系统写出完成后不关闭该流，调用方仍可继续写入后续内容

#### Scenario: 并发生成互不干扰
- **WHEN** 多个线程共享同一个选项对象并发生成不同文本的二维码
- **THEN** 每次调用各自返回对应文本的图片，不出现交叉污染

### Requirement: 二维码解码为文本
系统 SHALL 提供把二维码 PNG 解码为其编码文本的入口，支持从标准 Base64 文本（含或不含 `data:image/png;base64,` 前缀）、调用方输入流和指定文件三种来源读取。传入 data URI 时，系统 MUST 自动识别并去除该前缀后再解码，效果 MUST 与直接传入等价的纯 Base64 文本一致。系统 MUST 只识别 QR_CODE 码制。系统 MUST 能正确解码由本工具生成的、任意受支持配置（含中间提示文本叠加、自定义前景背景色）的二维码，解码结果 MUST 与生成时的原始文本完全一致。读取调用方提供的输入流时，系统 MUST NOT 关闭该流。

#### Scenario: 从 Base64 解码
- **WHEN** 调用方传入本工具生成的标准 Base64 字符串
- **THEN** 系统返回与生成时一致的原始文本

#### Scenario: 从 data URI 解码
- **WHEN** 调用方传入 `toDataUri` 返回的完整 data URI 字符串
- **THEN** 系统识别并去除固定前缀后完成解码，返回与生成时一致的原始文本，效果与直接传入去除前缀后的 Base64 文本一致

#### Scenario: 从输入流和文件解码
- **WHEN** 调用方分别通过输入流和文件路径提供同一张二维码图片
- **THEN** 两种来源都返回与图片编码内容一致的文本，且输入流未被关闭

#### Scenario: 解码叠加提示文本或自定义颜色的二维码
- **WHEN** 待解码图片是本工具生成的、配置了中间提示文本叠加或自定义前景背景色的二维码
- **THEN** 系统仍返回二维码本身编码的原始文本

#### Scenario: 拒绝无法解析的图片
- **WHEN** 输入字节不是有效图片，或图片中不包含可识别的 QR_CODE 二维码
- **THEN** 系统抛出标注为解码类别的工具异常，不返回部分结果或空字符串
