## Context

项目目前没有任何 IP 范围/网段匹配的代码。`HttpRequestUtils.getClientIp` 已经能解析出访问者的真实 IP 字符串（处理了多级代理、IPv4-映射 IPv6 规范化），但判断"这个 IP 是否在允许访问的网段内"这一步完全是空白，调用方只能自己写。IP 范围匹配常见于访问控制场景：这个判断结果本身会直接影响"放行还是拒绝"，因此解析过程的正确性和确定性（不依赖网络、不会因为输入异常而产生意外的网络调用）比一般工具类更重要。

## Goals / Non-Goals

**Goals:**
- 同时支持 IPv4 和 IPv6，CIDR 表示法与起止地址表示法两种常见的 IP 范围表达方式。
- 纯本地字符串解析和数值比较，不发起任何网络调用（不使用 `InetAddress.getByName` 对非法字面量退化为 DNS 域名解析的能力），保证同一组输入任何时候、任何网络环境下结果都确定且立即返回。
- 范围表达式与待检查 IP 的地址族不匹配时，判定为不属于（`false`），不是异常——这是正常的"不匹配"结果，不是调用方的用法错误。
- 范围表达式本身格式错误（非法 IP、非法 CIDR 前缀长度、起始地址大于结束地址等）属于调用方配置错误，用 `IllegalArgumentException` 及早暴露，不要让错误配置静默返回 `false`（那样会被误判为"IP 不在白名单里"而不是"白名单本身写错了"，在生产环境里更难排查）。
- 不引入新的第三方依赖。

**Non-Goals:**
- 不做主机名解析（如果调用方传入的不是字面量 IP 地址而是域名，视为格式错误直接拒绝，不尝试 DNS 查询）。
- 不支持通配符表示法（如 `192.168.1.*`）；只支持 CIDR 和起止地址两种表示法，已覆盖绝大多数实际配置场景，通配符可以手工换算成等价的 CIDR 或起止地址。
- 不支持多值/数组形式的单个 `ipRange` 参数（如一个字符串里用逗号分隔多个网段）；需要匹配多个范围时使用 `isInAnyRange(String, Collection<String>)`，由调用方自行把配置拆分成集合。
- 不从 `HttpServletRequest` 读取或解析 IP（这是 `HttpRequestUtils.getClientIp` 的职责），本工具只接收调用方已经拿到的 IP 字符串。
- 不做 IPv4-映射 IPv6（`::ffff:a.b.c.d`）规范化；调用方如果拿到的 IP 可能是这种形式，应先用 `HttpRequestUtils` 已有的规范化规则处理（`getClientIp` 已经做了），再传入本工具。

## Decisions

- **手动实现 IPv4/IPv6 字面量文本解析为字节数组，不使用 `InetAddress.getByName`**：`InetAddress.getByName(String)` 对合法的 IP 字面量不会发起 DNS 查询，但对不合法的字面量或域名字符串会退化为真实的主机名解析，这意味着一个格式错误的输入（哪怕只是手误）可能触发一次网络调用（DNS 查询），这对一个用于访问控制判断的工具而言是不可接受的副作用（变慢、行为依赖网络环境、理论上可被用作间接的 DNS 探测手段）。手动解析保证整个工具在任何输入下都是纯本地计算，不发起任何 I/O。
  - IPv4：按 `.` 分成 4 段，每段是 0-255 的十进制数，不允许前导零歧义以外的其他格式（保持实现简单，只覆盖标准点分十进制）。
  - IPv6：标准 8 组冒号分隔的十六进制文本，支持 `::` 压缩零段（最多出现一次），支持结尾内嵌 IPv4 形式（如 `::ffff:192.168.1.1`）。不支持区域 ID 后缀（如 `fe80::1%eth0`）——这是 Non-Goal，链路本地地址的区域标识与"网段匹配"场景基本不相关。
- **统一把"IP 范围"解析为 `(地址族, 起始地址数值, 结束地址数值)` 三元组，CIDR 和起止地址两种语法最终落到同一套比较逻辑**：CIDR 转换为起止地址——用前缀长度算出主机位位数 `hostBits`，起始地址 = 把地址的低 `hostBits` 位清零（网络地址），结束地址 = 把低 `hostBits` 位全部置一（广播/最后一个地址）；起止地址语法直接解析两端。地址数值用 `java.math.BigInteger`（以无符号方式从字节数组构造）表示，天然统一处理 32 位和 128 位地址，不需要为 IPv4/IPv6 分别写比较逻辑。判断"属于"就是 `start <= 待检查地址数值 <= end`。
- **只有一个单独 IP 字符串（既不含 `/` 也不含 `-`）的 `ipRange` 按"只包含它自己的范围"处理**（起始地址 = 结束地址 = 该地址）：这让调用方的白名单配置可以自由混用"单个 IP"和"网段"，不需要为单个 IP 的情况额外包一层 `/32` 或 `/128`。
- **地址族不一致判定为不属于（`false`），不是异常**：IPv4 规则不应该对 IPv6 请求生效、反之亦然，这是正常的"配置的规则对这类地址不适用"，属于业务上合法的不匹配结果；只有"范围表达式本身解析不出合法的地址族/地址"才是异常。
- **`isInAnyRange` 对 `null` 集合或集合中出现 `null` 元素抛 `IllegalArgumentException`，对空集合返回 `false`（不抛异常）**：空白名单意味着"没有任何规则放行"，是合法的业务状态（拒绝所有），调用方可能就是想表达这个意图；但集合里混入 `null` 元素几乎总是调用方拼装配置时的疏漏，应该尽早报错。
- **CIDR 前缀长度按地址族校验上限（IPv4 最大 32，IPv6 最大 128），超出或为负数时抛 `IllegalArgumentException`**；起止地址语法下起始地址数值大于结束地址数值同样抛 `IllegalArgumentException`——这两类都是"范围表达式本身不自洽"的配置错误。

## Risks / Trade-offs

- **自行实现的 IPv6 解析覆盖标准文本表示法，但不是对 RFC 4291 的完整实现**：不支持区域 ID（`%`后缀），对一些极少使用的历史写法（如全部用内嵌 IPv4 形式表示而非仅限最后 32 位）可能不覆盖；测试会覆盖标准全写、`::` 压缩、内嵌 IPv4 等主流写法，但如果未来发现某种合法写法未被支持，需要单独补充。
- **`BigInteger` 做地址数值比较在性能上比原生整数运算慢**：对 IP 范围匹配这种调用频率的场景（通常是单次请求级别的判断，不是紧密循环）可以忽略，用统一、不易出错的实现换取代码简洁性是合理的取舍。
