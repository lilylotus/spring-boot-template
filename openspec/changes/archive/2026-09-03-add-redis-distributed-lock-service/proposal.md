## 为什么

当前模板已有 Redis 缓存工具，但后续业务服务尚无统一的跨实例并发锁入口。新增公共锁服务，集中处理抢锁、等待、租期与安全释放，避免业务各自实现锁协议导致误删其他持有者的锁。

## 变更内容

- 提供可通过构造器注入的分布式锁服务；常用入口只需传入业务锁键（回调入口另传业务回调），等待时间、租期和续期间隔均使用可配置的生产推荐默认值，同时保留显式时长入口供特殊业务使用。
- 每次获取使用独立持有者令牌，获取与过期设置原子执行，释放时原子比较令牌，避免旧持有者误删新锁。
- 提供手动释放与同步业务回调两种入口；回调入口封装获取、执行、异常传播和最终释放。
- 为成功获取的锁自动续期：在持有者身份仍匹配时延长原租期；续期失败、身份不匹配或 Redis 续期异常时标记锁所有权已丢失并停止续期。
- 区分锁竞争超时、线程中断、Redis 故障和锁所有权丢失；未获取到锁绝不执行业务。
- 使用独立锁键命名空间，补充中文接入说明、无基础设施单元测试及真实 Redis 并发集成测试。
- 首版为非可重入、非公平、可自动续期的租期锁；不包含注解切面、读写锁、多锁组合、远程锁管理接口或独立服务部署。

## 能力

### 新增能力

- `redis-distributed-lock`: 面向业务服务的跨实例互斥、限时获取、安全释放和同步回调执行契约。

### 修改能力

无。现有 `redis-utils` 的缓存命令和序列化契约保持不变。

## 影响范围

- 新增 `com.example.template.redis.lock` 下的公共接口、实现、锁句柄及相关异常类型。
- 复用 Spring Data Redis 的连接工厂和字符串模板，不新增生产依赖，不改变现有 JSON 缓存模板。
- 新增锁命名空间、默认等待时间、默认租期、续期间隔及调度执行器配置、测试和 `docs/redis-distributed-lock.md`；无新增 HTTP 接口或全局异常映射。
- 互斥仅覆盖同一 Redis 数据库、相同命名空间和业务锁键的有效租期；自动续期仅在当前持有者正常运行且 Redis 可访问时保持租期，调用方仍必须在数据库提交后释放锁。
- Redis 锁不能替代数据库唯一约束、幂等和业务条件更新；进程长暂停、续期失败、锁键被驱逐及主从故障切换均可能破坏业务互斥，不能宣称严格一次执行。

## 确认要求

本次方案已加入自动续期及默认调用参数。默认配置建议等待 3 秒、租期 30 秒、续期间隔 10 秒；用户需确认续期失败时服务不继续宣称持锁、同步回调会在结束时以所有权丢失失败反馈，以及仍不提供可重入能力后，再实施设计与任务清单。
