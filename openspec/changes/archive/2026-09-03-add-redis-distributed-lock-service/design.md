## 背景

动机和范围见 `proposal.md`。当前项目使用 Spring Data Redis 与 Lettuce，`RedisConfig` 的对象模板采用 JSON 值序列化，`RedisUtils` 仅负责缓存命令。尚无锁公共接口，不能直接用缓存工具的先判断后写入或普通删除组合实现锁。

当前 `application.yml` 的 Redis 指向 `10.4.100.124:6379`，而非仓库说明中的本机地址。测试不得自动连接该地址或清空其数据库；必须显式指定独立测试 Redis。

## 目标与非目标

- 在单个共享 Redis 主节点健康、锁未被提前移除且租期有效的条件下，提供跨进程短任务互斥。
- 公共入口采用服务接口与构造器注入，不依赖静态上下文工具，也不新增 Controller。
- 常用入口采用生产推荐默认等待时间和租期；高级入口仍允许调用方显式覆盖。自动续期仅在当前持有者可正常续期时延长该租期，接口不承诺无限期持有、严格一次执行或数据库事务一致性。
- 首版不做可重入、公平排队、异步回调、注解切面和隔离令牌机制。

## 设计决策

### 1. 复用已有客户端与字符串序列化

新增 `DistributedLockService` 接口、`RedisDistributedLockService` 实现，放入 `com.example.template.redis.lock`。注入 Spring Boot 提供的 `StringRedisTemplate`，复用现有 `RedisConnectionFactory`，不修改 JSON 模板或缓存工具。

获取使用带过期时间的 `setIfAbsent`，对应单条原子 `SET NX PX`。释放使用 `DefaultRedisScript<Long>`，在一次 Lua 执行中比较令牌并删除。脚本仅涉及一个锁键，键和令牌均采用字符串序列化；不得先读取后执行普通删除，不提供强制解锁方法，不在事务或流水线中执行锁命令。

备选方案为引入 Redisson。其可重入与自动续期能力适合更复杂需求，但本次先限定为短任务基础锁，避免新增客户端和维护两套连接配置；如需续期，必须重新确认该选型。不能用本地线程锁替代跨实例互斥。

### 2. 公共接口与锁所有权

- `tryLock(key)` 返回 `Optional<RedisLockHandle>`，使用配置默认等待时间与租期；`tryLock(key, waitTime, leaseTime)` 作为高级覆盖入口。等待结束仍未成功返回空，允许高级入口以零等待进行单次尝试。
- `unlock(handle)` 返回布尔值：仅匹配当前持有者并删除成功时为真；重复释放、已过期或所有权变化时为假。
- `executeWithLock(key, Supplier<T>)` 返回业务结果（允许为空）并使用默认参数；另提供 `Runnable` 重载和显式时长的高级重载。未获取到锁抛出 `LockAcquisitionException`。
- 获取及回调入口允许向调用方传播 `InterruptedException`；异常信息使用中文。
- `RedisLockHandle` 为不透明的不可变句柄，包含完整锁键和每次尝试生成的随机 UUID 令牌；构造器非公开，不提供令牌读取接口，不在日志或 `toString` 暴露令牌。持有者以句柄令牌识别，而不是线程编号。
- 句柄不是可重入计数器。同线程再次获取相同键也按竞争处理；调用方只能在业务结束后交出句柄执行释放。

### 3. 自动续期与所有权状态

获取成功后，服务为该句柄注册单线程守护任务。初始续期在租期三分之一处执行，后续使用同一间隔；租期不足一秒时拒绝获取，避免调度误差使自动续期失去意义。每次续期使用 Lua 脚本：仅当锁键的令牌仍等于句柄令牌时，才以原租期更新 TTL；脚本返回成功、所有权不匹配或键不存在。禁止使用无条件 `PEXPIRE`。

句柄维护本地原子状态：`ACTIVE`、`LOST`、`RELEASING`、`RELEASED`。手动释放或回调最终清理先停止后续调度，再执行比较令牌删除；已经在途的续期和释放都由 Redis 脚本比较同一令牌，顺序竞争不会续期其他持有者的锁。句柄对调用方暴露只读的所有权丢失状态，不暴露令牌。

续期脚本返回所有权不匹配、键不存在或抛 Redis 异常时，立即标记 `LOST` 并停止续期。服务不使用旧令牌重建锁、不无条件重试，也不能强行中断已开始的任意业务代码；同步回调在业务返回前后检测 `LOST`，并以 `LockOwnershipLostException` 反馈。手动持有者必须检查句柄状态，并让业务通过幂等、条件更新等机制处理可能已发生的副作用。

守护任务使用受 Spring 管理的专用 `TaskScheduler`/调度执行器，线程命名含锁服务前缀，应用关闭时取消任务并有界等待，禁止为每个锁创建非托管线程。调度拒绝或关闭也视为续期失败并标记失锁。续期调度和 Redis 调用不得继承或泄露请求 MDC；调度日志只记录锁键和状态，绝不记录令牌。

备选方案为 Redisson watchdog。其提供成熟的续期实现，但会新增客户端、配置和运行时行为；当前服务使用已有 Spring Data Redis，保持依赖与连接模型稳定。不能把本地定时器或无条件 TTL 更新视为安全续期。

### 4. 有限等待与时间处理

校验非空白业务键、非空时长及回调，等待不得为负，租期至少 1 毫秒，所有时长要求毫秒精度且可安全转换为纳秒；拒绝零租期、负值、亚毫秒时长和溢出。公共服务入口通过明确的参数检查保护非 HTTP 调用，不依赖 Controller 校验。

以 `System.nanoTime` 计算已用时间，不使用系统日期计算超时。第一次立即尝试，失败后每次最多休眠 50 毫秒并裁剪到剩余等待时间，重试前检查截止时间和线程中断，避免忙循环。重试使用新令牌。

非零等待超过预算后不再发新请求；若已发出的成功请求返回时超过等待预算，则安全释放并返回未获取。零等待允许一次 Redis 往返。成功应答耗时若已达到租期，则安全释放并抛出 `LockOwnershipLostException`，绝不交出已知失效句柄或执行业务。

等待预算不是硬实时限制：在途 Redis 命令及清理耗时仍由客户端连接、命令和连接池超时决定，文档明确这一点。进入前或重试休眠中被中断，直接退出；成功应答后发现中断时先安全释放再传播中断，清理异常作为附加异常保留。

### 5. 回调与异常优先级

取得句柄后仅执行一次同步回调，不重试业务。业务正常返回、抛运行时异常或错误都必须在最终清理阶段尝试安全释放。

- 业务成功、句柄仍有效且释放成功：返回原业务结果。
- 业务成功但自动续期已标记失锁：抛出 `LockOwnershipLostException`，不把已知失锁报告为成功；这并不撤销已经发生的业务副作用。
- 业务成功但释放返回假：抛出 `LockOwnershipLostException`，不把已知失锁报告为成功；这并不撤销已经发生的业务副作用。
- 业务成功但释放发生 Redis 错误：传播基础设施异常。
- 业务抛异常或错误，同时释放失败或失锁：保持原始业务异常为主异常，将清理异常或失锁异常作为附加异常保留。
- Redis 获取异常直接传播，不能降级成本地锁、锁竞争失败或继续执行回调；不确定是否写入的锁由租期回收，不做无令牌删除。

业务数据库事务必须在锁内启动并在释放前提交。接入说明采用外层获取锁、回调内通过 `TransactionTemplate` 或独立事务服务完成事务的方式；不建议在已开启外层事务的方法中调用回调入口后立即释放。该服务不承诺自动协调调用方事务。

### 6. 锁键命名与配置

新增 `template.redis-lock.key-prefix`，默认 `lock:${spring.application.name}:`，以及 `wait-time`、`lease-time`、可选 `renewal-interval`。默认等待时间为 3 秒，默认租期为 30 秒，默认续期间隔为 10 秒；未配置间隔时按租期三分之一调度。显式间隔必须为正、毫秒精度且短于租期。配置绑定类提供相同默认语义并校验非空白。最终键为此前缀与调用方的业务键直接拼接，不隐式裁剪或改变业务键。业务键建议使用 `order:submit:订单编号` 等稳定业务资源标识。

同一业务的多实例必须使用相同 Redis 数据库和命名空间。不同服务需要共同互斥时，应明确配置同一个前缀；不同环境应隔离数据库或前缀。运行时改变前缀会拆分锁域，必须在停止相关业务后协调变更。

### 7. 测试与接入文档

- 单元测试使用 Mockito 和可控时间、休眠与调度测试接缝，覆盖原子获取参数、令牌唯一性、安全释放与续期脚本、竞争与超时、中断、续期失败、释放竞争、非法参数、Redis 故障及回调清理异常优先级，不连接任何真实基础设施。
- 独立集成测试使用显式环境变量启用并提供测试 Redis 地址与认证，通过专用随机键前缀隔离。只加载锁组件与最小 Redis 配置，不启动 MySQL、Nacos 或全应用上下文。
- 集成测试验证两个独立客户端竞争同键仅一个成功、不同键独立、释放后接手、租期到期接手、旧句柄无法删除新锁，并通过屏障和有界等待控制并发。只能清理本测试创建的键，禁止 `FLUSHDB`、`FLUSHALL` 和全库扫描删除。
- `docs/redis-distributed-lock.md` 提供构造器注入、手动释放、同步回调、续期间隔、所有权丢失、事务边界、跨服务前缀配置和测试启用命令；为所有新增 Java 类型与非平凡方法补充中文说明。

## 风险与取舍

- 进程长暂停、调度延迟、Redis 异常或驱逐使续期失败并提前失锁 → 显式配置覆盖最坏调度延迟的租期和余量，使用幂等、数据库唯一约束或条件更新；不能依靠续期或释放校验阻止已经失锁的进程继续写入。
- 主从异步复制与故障切换可能产生并行持有者 → 本实现不是强一致锁，也不是 Redlock；强一致场景须另选协调机制，并在受保护存储层落实隔离令牌或等价校验。
- 共享缓存 Redis 的内存驱逐或管理员删键 → 部署说明要求保护锁命名空间，生产优先使用隔离的锁存储与不会驱逐有效锁的策略。
- 固定轮询与续期调度在高竞争或大量持锁时增加 Redis 负载且不公平 → 使用有界等待、受控调度器和可观测的任务数量；高吞吐排队或无限期长任务不在首版承诺内。
- 回调产生外部副作用后清理失败 → 明确失败不代表副作用未发生，禁止调用方盲目重试，要求幂等设计。

技术依据：[Redis 官方分布式锁说明](https://redis.io/docs/latest/develop/clients/patterns/distributed-locks/)。

## 部署与回退

新增能力不会自动锁住现有业务，也不改变已有缓存数据。后续业务显式注入并调用后才生效；上线前确认锁域、租期和事务边界。回退时先停止接入业务并等待现有租期结束，再撤销调用，不批量删除锁键。
