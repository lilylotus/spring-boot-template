# Design

## Context

当前项目是 Java 21 单模块 Gradle 工程，通用工具位于 `org.example.simple.util`，没有 Spring Web 依赖。
`build.gradle` 已由用户加入 Apache POI 5.5.1。参见 `proposal.md` 的变更动机及
`specs/xlsx-processing/spec.md` 的可观察行为。

标准 POI 用户模型会把整个工作簿保存在内存中，不适合作为大数据读取核心；同时，返回 `List` 的 API
必然随行数增长，因此不能将“低内存”建立在无限制列表返回值上。XLSX 的共享字符串表也可能随唯一文本数量增长，
读取路径需要避免直接把它全部保存在堆中。

## Goals / Non-Goals

**Goals:**

- 提供小数据场景易调用、大数据场景内存有界的同一组 XLSX API。
- 明确流所有权、默认限制、映射规则、错误位置和资源清理责任。
- 让对象和 Map 导入导出行为可测试、可配置且不依赖 Spring。
- 在受限堆内存测试中验证大量行和高基数字符串不会导致内存随总行数线性增长。

**Non-Goals:**

- 不支持 `.xls`、宏文件、密码保护文件、图片、图表、批注、透视表或合并单元格语义还原。
- 不计算公式、不刷新公式缓存，也不访问外部工作簿链接。
- 不提供 HTTP Controller、`MultipartFile` 重载、模板填充、复杂样式设计或 Excel 修复能力。
- 不保证调用方把每一行自行累计到集合时仍保持低内存，也不保证突破配置资源预算后继续处理。

## Decisions

### 1. 公共 API 分层

在 `org.example.simple.util.excel` 包新增静态门面 `ExcelUtils`，并将配置和扩展点拆为小型公共类型：

- `ExcelReadOptions`：工作表、标题/数据行、列表容量和输入资源限制，采用 builder 创建不可变实例。
- `ExcelWriteOptions`：工作表名称、每表数据行、行窗口、工作表数、临时文件和文本限制。
- `ExcelColumn`：标注对象字段的标题、顺序、必填、日期格式。
- `ExcelRowHandler<T>` 与 `ExcelRowContext`：逐行同步消费并通过布尔返回值请求提前停止。
- `ExcelProcessingException`：统一携带错误类别以及可用的工作表、行、列、标题和字段上下文。

门面分别提供对象和 Map 的 `read...List`、`read...Each`、`write...` 方法。写出接收
`Iterable<? extends T>`，因此 `List` 可直接传入，数据库游标等数据源也可按需取数。
上传层只需把 `MultipartFile.getInputStream()` 传入，避免工具包绑定特定 Web 框架。

选择独立配置类型而不是大量重载，是为了让资源上限在调用处可见并保持后续兼容性；选择同步回调而不是返回
`Stream`，是为了让解析器、压缩包和临时文件的生命周期完整包裹在一次方法调用中，避免调用方忘记关闭。

### 2. 对象映射契约

对象字段使用 `@ExcelColumn` 明确暴露，按 `order` 后再按声明顺序稳定排序。导入类必须有可访问的无参构造器，
允许字段定义在父类中；静态、瞬态和未标注字段不参与处理。标题负责匹配而不是依赖物理列号，因此工作表列顺序
变化不会错写字段。标题缺失、重复、必填空值、重复顺序或不支持类型均快速失败。

内置转换支持规范中列出的类型。普通文本单元格默认修剪前后空白，以符合业务导入的常见预期；调用方仍可将
`trimCellValues` 显式设置为 `false` 以保留原始空白。数字转换使用十进制语义并做范围和整数校验，
不通过 `double` 中转。日期按列定义格式解析。导出 `Long`、`BigInteger` 及可能损失 Excel 精度的十进制值时默认写为文本；
字符串始终按文本写入，即使以 `=`、`+`、`-` 或 `@` 开头也不创建公式。

对象字段转换不依赖 SAX 层是否开启修剪，而是使用 `String.isBlank()` 统一识别 `null`、空字符串和纯 Unicode 空白文本。
必填字段或基本类型遇到空值时抛出转换异常，可空引用字段映射为 `null`。因此关闭 `trimCellValues` 只保留非空文本的
前后空白，不允许纯空白内容绕过必填校验。

本期选择字段注解加无参构造器，而不是通用反射推断、JavaBeans 或 record 构造器映射，以减少模糊规则和额外依赖。
后续如需 record 或自定义转换器，应作为独立 capability 扩展。

### 3. 通用 Map 契约

Map 导入统一产生 `LinkedHashMap<String, String>`：键是处理后的标题，值是显示文本，缺失单元格为 `null`，
显式空字符串保持为空字符串。该契约比混合返回 POI 数字、日期和布尔对象更稳定，调用方无需依赖工作簿样式推断类型。

Map 导出接受 `LinkedHashMap<String, ?>`。显式列定义用 `LinkedHashMap<String, String>` 表达“数据键 → 标题”；
未提供时缓存且仅缓存首行以推断键和顺序。后续行允许缺少已知键并写空单元格，但出现未知键时失败，防止静默丢列。
空数据可以配合显式列定义写出标题；没有数据也没有列定义时生成一个无单元格的有效工作表。

### 4. SAX 读取与磁盘支持的共享字符串

读取先把调用方输入流按 `maxInputBytes` 上限复制到本工具创建的临时文件，再以只读方式打开 OPC 包。这样既支持
不可回退的上传流，又能在解析前识别 OOXML 包和实施压缩输入上限。工作表使用 `XSSFReader` 与 SAX 顺序读取，
只保留当前行、标题映射、样式元数据和固定大小缓存。

为避免高基数 shared strings 在线性占用堆内存，新增内部磁盘支持的共享字符串实现：顺序解析
`sharedStrings.xml`，把 UTF-8 文本写入临时数据文件，把定长偏移索引写入独立文件，读取时使用小型 LRU 缓存。
索引、字符串和输入临时文件共同受 `maxTempBytes` 约束。没有共享字符串表时直接处理 inline string。
解析器禁用 DTD 和外部实体，并沿用 POI 对 OOXML 压缩包的安全检查；不在请求处理中修改 POI 的 JVM 全局安全参数。

相比直接使用 `XSSFWorkbook` 或 `ReadOnlySharedStringsTable`，该方案实现更复杂，但避免工作簿和唯一字符串数量决定堆峰值。
相比把所有输入拒绝在很小文件限制下，该方案能满足生产环境大数据使用诉求。

### 5. SXSSF 流式写出与自动分表

导出使用 `SXSSFWorkbook`，默认行窗口为 100，开启临时 XML 压缩并禁用共享字符串表，使已刷新的行不留在堆中。
对象或 Map 数据从 `Iterable` 逐项拉取。达到配置的每表数据行上限或 XLSX 固有限制前创建新工作表并重复标题；
工作表名称经过非法字符处理和唯一化，达到最大工作表数时失败。

样式只预创建标题、文本、数字、布尔和每种日期格式的有限集合，禁止逐单元格创建样式。关闭工作簿并调用清理逻辑删除
SXSSF 临时文件。由于 `OutputStream` 不能回滚，写出失败时统一说明已有字节可能是不完整文件；若调用方需要原子文件替换，
应先输出到自己的临时文件再移动。

### 6. 有界默认值和提前终止

配置的初始默认值拟定为：普通文本单元格修剪开启、压缩输入 200 MiB、内部临时文件合计 1 GiB、列表 100,000 行、累计单元格
10,000,000 个、列 16,384 个、单元格文本 32,767 字符、工作表 100 个、每表数据行 1,048,575 行。
所有正数上限在 builder 构建时校验；调用方可以降低或在明确评估后提高，但不能配置为无限。

逐行处理器返回 `false` 时正常提前终止。处理器抛出的异常包装为统一异常并保留 cause。所有退出路径在 `finally` 中释放
OPC 包、SAX 输入、共享字符串文件、上传临时文件和 SXSSF 临时文件，但不关闭调用方的输入输出流。

选择硬上限加快速失败，是因为任何库都无法对任意输入、任意并发量和任意 JVM 堆大小承诺绝不发生 OOM；本设计保证的是
库自身没有随总行数无限增长的数据结构，并在受支持预算内保持内存有界。

### 7. 错误模型和日志边界

异常类型区分格式、配置、映射、转换、资源限制和 I/O 类别。行列使用面向用户的一基编号，并同时保留标题和 Java 字段名。
原始值只保留至多 128 个字符的摘要以及完整长度，避免把大型或敏感单元格写入错误信息。工具类不自行记录数据内容，
由调用方决定日志级别和脱敏策略。

### 8. 源码维护注释

Excel 包内所有公共类型和公共方法使用中文 Javadoc 说明用途、参数、返回值、异常及重要约束。内部实现类、内部字段和
非直观方法同样补充中文注释，重点解释 SAX 状态、临时文件预算、共享字符串磁盘索引、对象映射缓存、SXSSF 行窗口
和自动分表等维护风险较高的实现细节。简单访问器和语义直观的局部变量不重复描述代码本身，避免无效注释掩盖关键约束。

注释只补充维护信息，不改变既有 API、配置默认值、解析规则、异常模型或运行时行为；完成后通过 Javadoc 和测试验证
注释改动未引入编译问题。

## Risks / Trade-offs

- [磁盘支持的共享字符串实现增加代码与随机读取成本] → 使用定长偏移索引和小型 LRU，并覆盖重复、高基数字符串测试。
- [临时文件可能耗尽磁盘或被异常进程遗留] → 每次调用使用独立目录、实施字节预算并在所有可控退出路径清理；文档说明进程崩溃不在 JVM 清理保证内。
- [列表接口仍会随结果大小增加堆占用] → 默认限制 100,000 行，超限时提示逐行 API，并测试边界行为。
- [Excel 数字最多约 15 位有效精度，源文件中已丢失的精度无法恢复] → 精确整数导出为文本，导入发现目标为精确类型时不声称恢复源文件已损失信息。
- [公式缓存可能过期或不存在] → 从不执行公式，仅返回已有缓存；必填映射遇到无缓存结果时按缺失值报错。
- [调用方并发执行多个大任务会叠加磁盘与内存占用] → 限制按调用生效，文档要求服务层另行设置并发上限。

## Migration Plan

1. 保留用户已添加的 POI 5.5.1 依赖，新增工具 API 和测试，不改变现有工具行为。
2. 先由业务以非关键 XLSX 导入导出验证列定义、限制值和临时目录容量，再替换重复的 POI 代码。
3. 回滚时停止调用新 API 并移除新增包；本变更不包含持久化数据迁移。
