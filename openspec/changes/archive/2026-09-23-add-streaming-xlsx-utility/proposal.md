# Proposal

## Why

项目缺少统一的 XLSX 导入导出能力，业务代码如果直接操作 Apache POI，容易重复实现字段映射、类型转换、
异常定位和资源释放，并在大数据场景因一次性加载工作簿或结果集而耗尽堆内存。

## What Changes

- 新增仅支持 `.xlsx` 的 Excel 工具能力，提供基于 `InputStream`、`OutputStream` 的上传解析与导出接口。
- 支持按列定义将工作表解析为指定 Java 对象，并将对象数据导出为工作表。
- 支持将通用工作表解析为保持列顺序的 `LinkedHashMap` 数据，以及将 `LinkedHashMap` 数据导出为工作表。
- 同时提供便捷的有界 `List` 接口和逐行回调、惰性数据源接口；大数据处理过程保持内存有界，超出资源限制时给出明确错误。
- 增加标题、工作表、数据范围、类型转换、空值、日期格式和错误策略等可配置项，并提供包含工作表、行、列和字段信息的异常。
- 普通文本单元格默认去除前后空白，同时允许调用方通过读取选项显式关闭修剪以保留原始空白。
- 对象字段转换阶段统一把 `null`、空字符串和纯空白字符串判定为空值，确保必填字段不会接受空白内容。
- 对输入大小、行列数量、单元格文本、压缩包安全和临时文件进行约束与清理，便于服务端生产环境使用。
- 为 Excel 包内公共 API 和内部实现类补充中文类、字段及方法注释，说明职责、约束、单位、返回语义和异常行为，
  降低后续维护成本。
- 旧版 `.xls` 不在支持范围内，传入非 XLSX 内容时明确拒绝。

## Capabilities

### New Capabilities

- `xlsx-processing`: 定义 XLSX 对象/Map 导入导出、流式大数据处理、类型映射、资源限制及错误诊断行为。

### Modified Capabilities

无。

## Impact

- 新增 `org.example.simple.util.excel` 包下的 Excel 公共 API、配置、注解、回调及异常类型。
- 新增对应的 JUnit 5 功能、边界、异常和受限堆内存测试。
- 使用 `build.gradle` 中已加入的 Apache POI `poi`、`poi-ooxml` 5.5.1 依赖。
- 不新增 Spring Web 依赖；上传调用方通过文件上传对象取得 `InputStream` 后调用工具，工具不负责 HTTP 接口。
