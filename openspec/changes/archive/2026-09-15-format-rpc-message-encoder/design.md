## Context

本变更的动机见 `proposal.md`。RPC 包已包含客户端、协议编解码、服务发现、负载均衡、服务端和传输层实现，纯自动格式化无法为缺失的领域说明作出可靠判断。

## Goals / Non-Goals

**Goals:**

- 以 Java 四空格缩进、合理换行和单行不超过 120 字符为基线，统一整个 RPC 包的源码格式。
- 在保持行为不变的前提下，为公共契约、配置含义和复杂资源/并发处理补充准确的中文说明。

**Non-Goals:**

- 不重命名类型、字段或方法，不重排业务执行顺序。
- 不改变序列化、网络协议、线程模型、超时、资源释放或异常处理。
- 不引入格式化工具、依赖或代码生成产物。

## Decisions

### 逐文件人工格式化并保持最小语义差异

仅调整空白、换行、缩进和注释；表达式、调用顺序、可见性、声明顺序与字面量均保持不变。相比全局自动格式化，这能避免同时重写无关区域或改变现有用户未提交修改的内容。

### 注释以公共契约和关键约束为边界

公共类、接口、record、常量和方法在用途或约定不明显时添加中文 Javadoc；资源所有权、并发限制、协议约束等复杂私有成员补充行级说明。明显的 getter、简单赋值和语义直接的局部变量不添加冗余注释。

### 按子包分批验证

依次处理 `client`、`common`、`config`、`discovery`、`loadbalance`、`monitoring`、`server` 与 `transport`，每批检查格式和编译；完成后运行全部测试。这样能及时发现注释或排版意外触及语法的情况。

## Risks / Trade-offs

- [大范围格式差异掩盖逻辑改动] → 逐文件审阅差异，并用编译和全部测试确认行为未变。
- [注释与实现语义不一致] → 只描述从现有代码可直接验证的职责和约束，避免推测未来行为。
- [覆盖用户正在编辑的 RPC 文件] → 修改前检查工作区差异；对已有未提交改动的文件仅在确认无冲突后处理。
