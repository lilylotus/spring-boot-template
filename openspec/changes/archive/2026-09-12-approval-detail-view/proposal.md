# Change: 为待办和审批记录增加审批详情

## Why

当前“待我审批”和“审批记录”只展示业务类型、业务标识、当前级别和处理结果，审批人无法看到本次申请的具体数据，也无法了解完整审批链、已处理节点、当前节点和后续节点。

列表目前只以 `bizType + bizId` 表达业务身份。同一业务数据可能发生多次审批，仅靠这两个字段无法保证从某条历史记录打开的是同一次审批。因此详情能力需要提供稳定的审批实例标识，并保存发起时的审批链和数据快照。

## What Changes

- 待办列表和审批记录列表增加“详情”操作。
- 新增审批详情弹窗，展示本次审批状态、当前审批点、完整审批流程和审批数据。
- 完整流程按发起时的审批链展示所有节点，包括审批人、节点状态、审批动作、意见、到达时间和处理时间。
- 为待办和记录 DTO 增加稳定的 `approvalId`，详情按该 ID 查询，避免同一业务多次审批串单。
- 在 `approval_biz_link` 中保存发起人、审批人链快照和审批数据快照，配置变更不影响历史详情。
- 用户编辑审批的新快照同时包含修改前、修改后数据；用户新增展示申请创建的数据。
- 兼容已有审批：新字段为空时尝试从 Flowable 运行时/历史变量读取原审批人列表和 payload；确实无法恢复的部分明确显示“历史数据不可用”。
- 详情接口使用当前操作人校验访问范围：只有当前待办审批人或已经处理过该实例的审批人可以查看。

## Scope

### In Scope

- 审批关联表的详情快照字段及 Flyway V5 迁移。
- 审批详情防腐层 DTO、网关实现和 HTTP API。
- 用户新增/编辑发起审批时的数据快照格式。
- 审批中心详情入口和响应式详情弹窗。
- 后端集成测试、Controller 测试和前端构建/浏览器验证。

### Out of Scope

- 修改审批链配置方式和审批流转规则。
- 在详情弹窗中执行同意或驳回；操作仍使用现有审批操作弹窗。
- 审批附件、富文本表单、评论对话和催办。
- 给非参与审批的人开放详情。
- 对迁移前且 Flowable 历史数据已被清理的审批进行人工回填。

## Impact

- **Database**：新增 V5 迁移，为 `approval_biz_link` 增加可空快照字段。
- **Backend API**：列表响应增加 `approvalId`；新增 `GET /api/approval/instances/{approvalId}`。
- **Identity**：新发起的用户新增/编辑审批使用可表达前后值的 payload 包装格式。
- **Frontend**：审批中心新增详情按钮和详情弹窗。
- **Compatibility**：接口字段为增量添加；旧记录通过 Flowable 变量兜底，无法恢复时降级展示。

## Risks

- 快照包含手机号、邮箱等用户数据，详情接口必须按当前操作人校验参与关系，不能只凭 ID 公开查询。
- Flowable 历史清理后旧审批可能无法恢复审批人链或业务数据；页面必须区分“空数据”和“历史数据不可用”。
- 审批配置变化不能用于重建历史流程，必须优先使用发起时快照，禁止读取当前配置冒充历史配置。
