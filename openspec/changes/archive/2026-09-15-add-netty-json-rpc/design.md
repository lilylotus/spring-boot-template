## 背景

项目已包含 Netty 4.2、Jackson 3 和 JUnit 5，但目前只有简单入口类及日志测试，没有网络协议或服务抽象。设计需满足 `proposal.md` 和 `specs/netty-json-rpc/spec.md` 的行为约束，并保持公共组件、服务端、客户端三个包的依赖方向清晰。

## 目标与非目标

**目标：**

- 提供最小但完整的单进程服务注册、Netty 传输和客户端同步调用链路。
- 通过协议模型和序列化接口隔离传输层与 JSON 实现，便于后续扩展。
- 正确处理消息边界、并发请求、超时、远端异常和资源关闭。
- 让核心协议与调用行为可通过单元测试和本机环回集成测试验证。

**非目标：**

- 本次不实现服务发现、负载均衡、重试、认证、TLS、限流或链路追踪。
- 本次不实现异步代理、流式调用、回调、单向消息或跨语言兼容。
- 本次不提供 JSON 之外的序列化实现，也不保证协议的长期二进制兼容性。

## 技术决策

### 协议帧与公共模型

线格式采用四字节大端消息长度加 JSON 消息体。Netty 管线使用长度字段解码器和长度字段编码逻辑，以统一处理粘包与拆包。消息最大长度默认设为 8 MiB，并允许构造时覆盖。请求模型包含请求标识、服务名、方法名、参数类型名列表及参数值列表；响应模型包含请求标识、成功标记、字符串结果及错误信息。

选择长度前缀而不是换行分隔，是因为 JSON 字符串可包含换行且长度前缀能在解析前实施大小限制。首期不加入魔数、版本和序列化算法字段，以控制范围；若未来需要多协议兼容，再通过新帧头演进。

### 序列化边界

公共包定义消息序列化接口及 Jackson JSON 实现，编解码器只依赖该接口。请求参数使用 Jackson 树模型承载，响应结果使用 Jackson JSON 字符串承载；两者都只在已确定目标 Java 类型后执行转换，避免将任意客户端类型信息直接交给 Jackson 多态反序列化。`ObjectMapper` 在实例间复用，不启用默认多态类型功能。

服务端将方法返回值直接序列化为 UTF-8 JSON 字符串并写入 `RpcResponse.result`；因此整个响应再次序列化时，结果中的引号和控制字符会按 JSON 字符串规则转义。客户端收到成功响应后，将 `result` 的 UTF-8 字节交给 Jackson 按调用方声明类型反序列化。Java `null` 返回值对应非空文本 `null`，失败响应仍使用 Java `null` 作为结果字段。选择字符串而不是 `JsonNode` 可让响应模型不暴露 Jackson 树类型，但会产生一次字符串中间表示和外层 JSON 转义开销。

序列化器统一关闭“遇到未知属性即失败”的行为，以允许新版本发送方增加字段而不破坏旧版本接收方。`java.util.Date` 和 `LocalDateTime` 使用 `yyyy-MM-dd HH:mm:ss` 文本格式，调用方未指定时区时沿用 JVM 默认时区；该格式不携带时区或偏移量，因此首期不将其扩展到 `Instant`、`OffsetDateTime` 等具有明确时间线语义的类型。默认构造和传入 `ObjectMapper` 的构造方式必须应用相同规则，避免线协议随构造入口变化。

选择显式参数类型名是为了区分重载方法；替代方案是仅按实参数量和 JSON 形态推断，但该方案对数值类型、空值和重载存在歧义。

### 服务端结构

服务注册表以显式服务名映射到实现实例，只暴露实现所对应服务接口的公开方法。请求处理器完成查找、参数转换和反射调用，并将所有可预期失败转换为结构化失败响应。耗时业务方法从 Netty I/O 线程转移到独立执行器，防止阻塞连接读写；服务端关闭时依次停止接收连接、执行器和事件循环组。

### 客户端结构

客户端维护单连接、独立 `DefaultEventLoop`，以及以请求标识为键的 `Promise<RpcResponse>` 待完成调用表。发送请求前通过响应事件循环创建并登记 `Promise`；网络响应处理器只把匹配与完成任务提交给该事件循环，由它串行移除等待项并调用 `trySuccess`。写入失败、连接关闭和客户端关闭同样向该事件循环提交失败任务，避免不同线程直接竞争完成同一个调用。

公开入口继续提供同步 `invoke` 方法，调用线程通过 Netty `Promise.await(timeout)` 等待异步响应完成，随后在调用线程转换返回值。超时时调用线程以条件删除清理等待项，迟到响应不会完成其他调用。同步调用同时禁止在网络 I/O 事件循环和响应 `DefaultEventLoop` 中执行，防止阻塞任何负责推进响应的线程。关闭时先等待响应事件循环完成全部失败通知，再关闭连接和两个事件循环资源。

选择单连接是为了保持首期生命周期简单；连接池和自动重连留待后续需求。同步等待不得在 Netty 事件循环线程内调用，代码将检测并拒绝这种用法以避免死锁。

### Java 标识符约束

Java 类名、接口名、枚举名、`record` 名、方法名和字段名统一使用英文，不允许包含中文字符，测试代码同样适用。测试方法使用能表达预期行为的英文 `lowerCamelCase` 名称；测试说明、Javadoc、日志和字符串内容继续使用中文。该约束只调整源码可维护性，不改变 RPC 线协议中的服务名、方法名或用户数据使用中文字符串的能力。

## 风险与权衡

- 客户端提供的类型名可能用于探测类路径 → 仅允许匹配已注册服务接口的方法签名，不按任意名称实例化类型。
- 反射调用和 JSON 转换开销高于生成式编解码 → 首期优先可读性与可扩展性，通过隔离接口保留优化空间。
- 单连接故障会影响全部在途请求 → 连接关闭时快速失败所有等待项，暂不承诺自动重连。
- 独立响应事件循环增加一个客户端线程 → 关闭流程显式终止 `DefaultEventLoop`，并用串行完成换取清晰的响应顺序。
- 错误信息可能泄露内部实现 → 响应仅返回稳定错误类别和安全描述，完整堆栈只写入服务端中文日志。
- 业务执行器饱和可能导致延迟累积 → 使用有界队列并在拒绝任务时返回服务繁忙错误。
- 日期时间文本不携带时区信息 → `Date` 按 JVM 默认时区解释，跨时区部署时由启动参数统一 JVM 时区。
- 成功结果在外层响应中会被再次转义 → 通过专项测试覆盖字符串、对象和 `null`，并保留消息总长度上限。

## 迁移计划

本次为新增能力，无存量迁移。实现顺序为公共协议与序列化、服务注册与服务端、客户端调用、测试与示例。若验证失败，可删除新增的 `org.example.simple.rpc` 包及相关测试，不影响现有入口和日志配置。
