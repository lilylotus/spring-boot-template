## 背景与原因

现有 RPC 已实现单连接同步调用、JSON 序列化及业务线程隔离，但缺少多实例路由、主动超时、异步入口和完整生命周期治理。本次在现有实现上升级，形成可验证的生产设计与实现基线。

## 变更内容

- **BREAKING**：将四字节长度前缀改为十九字节固定头，包含魔数、版本、消息类型、序列化方式、八字节 requestId 和消息体长度；不自动兼容旧协议。
- 同时支持 JSON（编号 1）和 Protostuff（编号 2），默认 JSON，可按调用选择；响应保持请求编码，参数与结果使用序列化器无关载荷，取代旧 JSON 专用模型。
- 使用客户端实例共享的 `ConcurrentHashMap<Long, PendingRequest>`、`CompletableFuture` 和 `HashedWheelTimer` 统一同步、异步及超时完成路径，替换旧 `Promise` 机制。
- 新增服务发现抽象及 Nacos 实现，动态维护连接；提供轮询、平滑加权轮询、一致性哈希策略。
- 保持业务线程隔离，补齐有界准入、心跳、重连、分级超时、有限重试、优雅停机和可观测性。
- 显式提供面向生产的 Netty 默认参数，分别配置监听 Channel、已接受连接和客户端连接，覆盖线程、内存分配、TCP、背压及资源预算；线程数采用固定默认值并支持手动配置，禁止按 CPU 核数自动推导；所有参数可覆盖并在启动时校验。
- 提供可选 TLS/mTLS、服务方法白名单和资源上限，避免将示例直接等同于生产上线认证。
- 补充竞态、故障、多实例及生命周期测试，以及部署与容量验证说明。

## 能力

### 新增能力

- `production-netty-rpc`：规定升级后的协议、客户端请求生命周期、动态路由、服务端治理及生产验证要求。

### 修改能力

无主规范修改。现有 `netty-json-rpc` 只存在于已完成但未归档的 `add-netty-json-rpc` 变更中；本变更以当前代码为基线，明确取代其旧协议和客户端 Promise 决策，不修改其历史文档或代为归档。

## 影响范围

- 修改 `org.example.simple.rpc` 下现有实现及对应测试，新增发现、路由、配置和监控组件，保留单模块 Java 21 Gradle 结构。
- 保留同步调用入口及直连使用方式；协议标识模型改为 `long` 属于源码兼容性变更。
- 引入 Protostuff、Nacos SDK 与 Micrometer/OpenTelemetry 接入依赖；实施时验证与当前 Netty 4.2、Jackson 3 的依赖兼容性并锁定版本。
- 注册中心首期采用 Nacos；ZooKeeper 只预留接口，不同时实现。注册中心部署、监控后端部署和业务幂等存储由应用环境负责。
