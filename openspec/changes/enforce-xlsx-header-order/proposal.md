# Proposal

## Why

对象导入当前只检查必填标题是否存在，标题即使位于错误列也会继续按名称映射，无法及时发现上传模板的列顺序已经偏离 `@ExcelColumn` 声明。生产导入需要在读取数据行前同时校验标题名称、数量和列索引，避免错误模板被静默接受。

## What Changes

- **BREAKING**：对象导入要求 XLSX 标题列与对象的 `@ExcelColumn` 声明完整一致，不再接受标题乱序、缺列或额外列。
- 按现有列排序规则（先比较 `order`，相同时按继承层级和字段声明顺序）确定每个声明列的期望索引，并逐列比较实际标题。
- 标题不一致时在处理数据行前抛出映射异常，错误信息包含工作表、实际列号、期望标题和实际标题。
- 补充标题顺序一致、标题乱序、缺少声明列及存在额外列的对象导入测试。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `xlsx-processing`：对象导入的标题匹配从“按名称存在即可”调整为“标题数量和每个列索引均与声明顺序一致”。

## Impact

- 影响 `org.example.simple.util.excel.ExcelObjectMapper#validateHeaders` 的对象导入标题校验逻辑和相关 Javadoc。
- 影响依赖标题乱序、缺少非必填声明列或携带额外列的现有对象导入调用；这些文件将被明确拒绝。
- 不改变通用 Map 导入、对象导出、数据类型转换和流式内存模型，也不增加第三方依赖。
