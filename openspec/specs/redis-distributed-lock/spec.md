# redis-distributed-lock Specification

## Purpose

为业务服务提供统一的跨实例短任务并发锁能力，约定限时获取、固定租期、安全释放和同步回调的可观察行为，明确锁失效与基础设施故障的处理边界，避免业务重复实现不安全的锁协议。

## Requirements

### Requirement: 共享锁域内的互斥获取
系统 MUST（必须）提供可注入的公共锁服务。在共享 Redis 存储健康、锁未提前移除且租期有效的前提下，同一数据库、命名空间和业务键只允许一个有效持有者；不同键独立竞争。锁服务不得改变现有缓存读写契约。

#### Scenario: 多实例竞争同一键
- **WHEN** 多个独立实例同时立即尝试获取同一锁域内的相同业务键
- **THEN** 只有一个获取成功，其余返回未获取，且不能删除或覆盖成功者的锁

#### Scenario: 不同业务键互不阻塞
- **WHEN** 一个业务键被持有，另一个调用方获取相同锁域内的不同业务键
- **THEN** 后者可独立获取成功

#### Scenario: 显式共享跨服务锁域
- **WHEN** 不同服务配置相同数据库和命名空间，并获取相同业务键
- **THEN** 它们竞争同一把锁；配置不同命名空间时互不影响

### Requirement: 有限等待与中断
系统 MUST（必须）支持零等待的单次尝试和有限等待；竞争超时返回未获取，不无限阻塞或忙循环。等待预算限制重试，客户端命令超时限制在途调用，不承诺硬实时返回。中断必须传递给调用方，不得继续发起重试或执行业务。

#### Scenario: 使用生产推荐默认参数获取锁
- **WHEN** 调用方只提供业务锁键调用常用获取入口
- **THEN** 系统使用配置的默认等待时间 3 秒和默认租期 30 秒尝试获取锁，调用方无需传入时长参数

#### Scenario: 等待期间锁被释放
- **WHEN** 锁被其他持有者占用，但在等待预算结束前释放且本次成功获取
- **THEN** 调用方获得新的持有权

#### Scenario: 等待预算耗尽
- **WHEN** 所有获取尝试均因占用而失败且等待预算已耗尽
- **THEN** 返回未获取，不再发送新的获取请求

#### Scenario: 成功应答晚于非零等待预算
- **WHEN** 非零等待请求取得锁，但成功应答抵达时等待预算已耗尽
- **THEN** 系统尝试安全释放本次锁并返回未获取；释放异常不能静默吞掉

#### Scenario: 获取过程被中断
- **WHEN** 调用前线程已中断或等待过程被中断
- **THEN** 系统传播中断，不再重试；已确认取得的锁必须尝试安全释放

### Requirement: 固定租期与非可重入行为
系统 MUST（必须）在获取锁的同一原子操作中设定调用方指定的正租期；不创建永久锁、不支持可重入。成功获取后系统必须在当前持有者身份仍匹配时自动续期，续期使用原租期，且不得无条件延长其他持有者的锁。超过租期、续期失败或所有权丢失后不得承诺原业务仍受保护。

#### Scenario: 正常持有期间自动续期
- **WHEN** 有效持有者未释放、仍可访问 Redis 且令牌匹配
- **THEN** 系统在租期届满前自动将锁的剩余有效期恢复为原租期

#### Scenario: 持有者未主动释放
- **WHEN** 持有者退出且不执行释放，自动续期停止，锁达到最后一次设置的租期
- **THEN** 锁自动过期，其他调用方可重新获取

#### Scenario: 同线程重复获取
- **WHEN** 同一线程在租期内再次获取已经持有的同一业务键
- **THEN** 按锁竞争处理，不直接成功也不延长原租期

#### Scenario: 获取应答已消耗租期
- **WHEN** 从获取请求发出到收到成功应答的时间已经达到租期
- **THEN** 系统不交出已知失效的持有权或执行业务，尝试安全释放并报告所有权丢失

#### Scenario: 续期发现所有权丢失
- **WHEN** 自动续期时锁键不存在或其持有者身份不再匹配
- **THEN** 系统停止续期并标记该句柄所有权已丢失，后续释放不得删除当前锁

#### Scenario: 自动续期发生 Redis 故障
- **WHEN** 自动续期命令因 Redis 连接或执行错误失败
- **THEN** 系统停止续期并标记所有权已丢失，不重建锁或把该故障视为续期成功

### Requirement: 按持有者身份安全释放
系统 MUST（必须）使用每次独立获取的持有者身份进行原子条件释放，不得仅根据业务键删除锁。只有当前身份匹配且删除成功才报告释放成功。

#### Scenario: 正常释放后重新获取
- **WHEN** 当前有效持有者释放锁
- **THEN** 释放返回成功，其他调用方可获取该锁

#### Scenario: 旧持有者释放新锁
- **WHEN** 原锁过期后被新持有者获取，旧持有者随后尝试释放
- **THEN** 返回释放失败，新持有者的锁及其租期保持不变

#### Scenario: 重复释放
- **WHEN** 已成功释放的句柄再次用于释放
- **THEN** 返回释放失败，不影响之后出现的锁

### Requirement: 受保护业务同步执行与最终释放
系统 MUST（必须）提供同步回调入口，只有获取成功后才能执行回调，且仅执行一次；正常结束或抛异常均尝试释放。竞争超时以明确的获取失败异常反馈。业务异常优先于清理异常，自动续期已知失锁不得被包装为正常成功。

#### Scenario: 回调正常完成
- **WHEN** 获取成功，回调正常返回且释放成功
- **THEN** 原样返回回调结果，包括空结果

#### Scenario: 回调获取失败
- **WHEN** 等待预算耗尽仍未取得锁
- **THEN** 抛出获取失败异常，回调调用次数为零

#### Scenario: 业务异常和释放异常同时出现
- **WHEN** 回调抛出异常或错误，随后清理也失败
- **THEN** 传播原始业务异常或错误，把清理异常作为附加异常保留，不自动重试业务

#### Scenario: 业务成功但锁已失效
- **WHEN** 回调返回后释放发现锁已过期或属于其他持有者
- **THEN** 报告所有权丢失，而非正常成功；不承诺撤销已产生的副作用

#### Scenario: 回调执行期间续期失败
- **WHEN** 同步回调正在执行，自动续期发现所有权丢失或 Redis 故障
- **THEN** 系统不能强制中断已执行的回调；回调结束后报告所有权丢失，并停止后续续期

### Requirement: 参数与基础设施故障不得绕过锁
系统 MUST（必须）拒绝空白业务键、空时长、负等待、非正租期、非毫秒精度或不可安全转换的时长，以及空回调。Redis 错误必须传播，不能伪装成锁竞争、成功或降级为无锁执行业务。

#### Scenario: 输入参数非法
- **WHEN** 调用方传入任一非法参数
- **THEN** 在访问 Redis 和执行业务之前报告参数错误

#### Scenario: 获取发生 Redis 故障
- **WHEN** 获取命令因连接或执行错误失败
- **THEN** 传播基础设施异常，不执行回调，不把它当作正常竞争失败

#### Scenario: 释放发生 Redis 故障
- **WHEN** 业务执行成功，但释放命令失败
- **THEN** 传播基础设施异常，不报告释放成功

### Requirement: 明确接入边界
系统 MUST（必须）提供中文接入说明，覆盖锁域、固定租期、自动续期、同步回调、手动最终释放和事务提交后释放，明确主从切换、驱逐、长暂停、调度延迟和续期失败下的互斥局限，不宣称严格一次执行。

#### Scenario: 业务包含数据库事务
- **WHEN** 开发者参考说明接入带事务的受保护业务
- **THEN** 示例在锁内开始并完成事务，提交后才释放，并提示唯一约束、幂等和条件更新仍由业务保证

#### Scenario: 业务耗时不可控
- **WHEN** 开发者评估长任务或高一致性业务接入
- **THEN** 文档明确自动续期不能覆盖进程暂停、Redis 故障或无限期任务，且无隔离令牌，不应单靠本服务保障此类任务的数据一致性

### Requirement: 常用调用采用生产默认参数
系统 MUST（必须）提供只要求业务锁键的常用获取入口，以及只要求业务锁键和业务回调的常用同步执行入口。默认等待时间必须为 3 秒，默认租期必须为 30 秒，默认续期间隔必须为 10 秒；调用方必须能够通过配置统一覆盖这些默认值，并可在高级入口显式覆盖时长。

#### Scenario: 使用默认参数执行同步业务
- **WHEN** 调用方以业务锁键和业务回调调用常用同步执行入口
- **THEN** 系统使用当前配置的默认等待时间和租期完成获取、自动续期及最终释放

#### Scenario: 环境统一调整默认参数
- **WHEN** 部署环境配置新的默认等待时间、租期或续期间隔
- **THEN** 未显式传入时长的调用统一使用新配置，显式时长调用保持其指定值
