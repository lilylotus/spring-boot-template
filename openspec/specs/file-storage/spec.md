# file-storage Specification

## Purpose

为业务模块提供通用、可直接复用的文件上传与下载能力：文件落盘存储、随机化存储文件命名、文件元信息记录表，
以及基于记录状态的下载权限控制，避免各业务模块各自实现一套文件存储逻辑。

## Requirements

### Requirement: 文件上传
系统 SHALL 提供一个通用文件上传接口，接收 multipart 文件，将文件保存到磁盘存储目录，并把文件的元信息
写入文件上传记录表，最终返回该记录的主键 id 供后续下载使用。

#### Scenario: 上传单个文件成功
- **WHEN** 调用方以 multipart/form-data 方式提交一个非空文件
- **THEN** 系统将文件内容写入磁盘存储目录，在文件上传记录表中新增一条状态为"正常"的记录，并返回该记录的 id

#### Scenario: 上传空文件被拒绝
- **WHEN** 调用方提交的文件内容为空（大小为 0）或未携带文件字段
- **THEN** 系统拒绝请求，返回统一格式的错误响应，且不写入磁盘、不创建记录

#### Scenario: 上传文件超出大小限制被拒绝
- **WHEN** 调用方提交的文件大小超过系统配置的单文件大小上限
- **THEN** 系统拒绝请求，返回统一格式的错误响应，且不写入磁盘、不创建记录

### Requirement: 存储文件命名规则
系统 SHALL 使用"随机字符串 + 原始文件后缀名"作为磁盘存储文件名，与调用方提交的原始文件名解耦，避免
文件名冲突、路径穿越等问题；原始文件名只保存在记录表中用于下载时还原。

#### Scenario: 磁盘存储文件名与原始文件名不同
- **WHEN** 系统为一次上传生成磁盘存储文件名
- **THEN** 生成的文件名由随机字符串加上从原始文件名提取的后缀组成，不直接复用调用方提交的原始文件名

#### Scenario: 原始文件名不含合法后缀
- **WHEN** 调用方提交的原始文件名不包含"."分隔的后缀（或后缀为空）
- **THEN** 系统仍能生成合法的磁盘存储文件名（不含后缀部分），上传流程正常完成

### Requirement: 文件元信息记录
系统 SHALL 为每一次成功上传在文件上传记录表中保存一条记录，至少包含：原始文件名、磁盘存储文件名（含相对
路径）、文件状态。文件状态只有"正常"和"失效"两种取值，新建记录的初始状态为"正常"。

#### Scenario: 记录包含还原下载所需的信息
- **WHEN** 查询一条已成功上传的文件记录
- **THEN** 该记录同时包含原始文件名、磁盘存储文件名和当前文件状态三项信息

### Requirement: 按 id 下载文件
系统 SHALL 提供一个通用文件下载接口，调用方通过文件上传记录表的主键 id 请求下载；系统据此定位磁盘上的
存储文件，以记录中的原始文件名作为下载文件名返回文件内容。

#### Scenario: 下载存在且状态正常的文件
- **WHEN** 调用方使用一个状态为"正常"且磁盘文件存在的记录 id 发起下载请求
- **THEN** 系统返回该文件的完整二进制内容，响应中的文件名使用记录中的原始文件名

#### Scenario: 下载不存在的记录 id
- **WHEN** 调用方使用一个在文件上传记录表中不存在的 id 发起下载请求
- **THEN** 系统返回"资源不存在"的错误响应，不返回任何文件内容

### Requirement: 文件状态控制下载权限
系统 SHALL 依据文件上传记录的状态控制是否允许下载：状态为"正常"的记录可以下载；状态为"失效"的记录一律
拒绝下载，即使磁盘上的物理文件仍然存在。

#### Scenario: 失效状态的文件拒绝下载
- **WHEN** 调用方使用一个状态为"失效"的记录 id 发起下载请求
- **THEN** 系统拒绝下载并返回明确说明"文件已失效"的错误响应，不返回文件内容
