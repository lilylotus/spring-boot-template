# 二维码工具类使用说明

`QrCodeUtils` 位于 `org.example.simple.util.qrcode`，把一段文本生成 PNG 二维码，支持四种输出形态、支持在二维码中间叠加提示文本，并支持反向把二维码 PNG 解码回原始文本。

- 只处理 PNG，只识别/生成 QR_CODE 码制。
- 工具**不会关闭**调用方传入的 `OutputStream`/`InputStream`，由调用方管理生命周期。
- 工具无可变静态状态，`QrCodeOptions` 不可变，均可安全跨线程共享和重复使用。
- 参数非法抛出 `IllegalArgumentException`；编码、字体、解码或读写失败抛出 `QrCodeException`。

## API 速查

| 方法 | 返回 / 效果 |
| --- | --- |
| `toBase64(text[, options])` | 标准 Base64 文本，不含 data URI 前缀 |
| `toDataUri(text[, options])` | `data:image/png;base64,...`，可直接用作 `<img src>` |
| `writeToFile(text, file[, options])` | 写入指定文件，自动建父目录，覆盖同名文件 |
| `write(text, output[, options])` | 写入调用方输出流，不关闭该流 |
| `decode(base64OrDataUri)` | 把 Base64 文本或 data URI 解码回原始文本 |
| `decode(input)` | 从调用方输入流读取 PNG 并解码，不关闭该流 |
| `decode(file)` | 从指定文件读取 PNG 并解码 |

四个生成方法族共用同一条渲染管线，相同文本和相同选项在四种形态下产生完全相同的 PNG 字节。未传 `options` 的生成重载等价于传入 `QrCodeOptions.defaults()`。

## 基本用法

```java
// 默认 300px、中等纠错，返回纯 Base64
String base64 = QrCodeUtils.toBase64("https://example.com/order/A-01");

// 前端直接渲染
String dataUri = QrCodeUtils.toDataUri("订单 A-01");

// 写入文件
QrCodeUtils.writeToFile("https://example.com/order/A-01", Path.of("build/qr/A-01.png"));

// Web 下载：写入响应流，工具不关闭该流
QrCodeUtils.write("https://example.com/order/A-01", response.getOutputStream());
```

待编码文本不能是 `null` 或空字符串，但**纯空白文本合法**（如仅含空格），会被当作正常内容编码。

## 解码：PNG 还原为文本

```java
String fromBase64 = QrCodeUtils.decode(base64);
String fromDataUri = QrCodeUtils.decode(dataUri);          // 自动识别并去除 data URI 前缀，无需手动处理
String fromFile = QrCodeUtils.decode(Path.of("build/qr/A-01.png"));

try (InputStream input = Files.newInputStream(Path.of("build/qr/A-01.png"))) {
    String fromStream = QrCodeUtils.decode(input);         // 工具不关闭该输入流
}
```

要点：

- `decode(String)` **同时接受纯 Base64 和完整 data URI**：入参以 `data:` 开头时自动识别并去除到第一个逗号为止的前缀，`toBase64`/`toDataUri` 的返回值都可以原样传回来解码，不需要调用方自己剥前缀。
- 只识别 **QR_CODE** 码制，不识别条形码、DataMatrix 等其他码制。
- 能正确解码本工具生成的任意受支持配置的二维码，包括中间提示文本叠加、自定义前景/背景色。
- 只处理已经是正向、完整的二维码图片，**不做旋转、透视校正等针对相机拍摄场景的图像预处理**；图片中包含多个可识别二维码时只返回其中一个，具体是哪一个不作保证。
- 只返回二维码中编码的原始文本，不对内容做业务层解析（不识别其中的 URL、JSON 等）。

## 生成选项 QrCodeOptions

`QrCodeOptions.defaults()` 或 `QrCodeOptions.builder()...build()`。选项对象不可变，构建时统一校验。

| 选项 | 默认值 | 范围 | 说明 |
| --- | --- | --- | --- |
| `size` | `300` | `[21, 4096]` | 图片边长（像素），二维码为正方形。实际输出边长可能因取整略大于请求值，不小于请求值 |
| `margin` | `1` | `[0, 32]` | 静区宽度，单位是**模块数**，不是像素 |
| `errorCorrection` | `MEDIUM` | 非 null | 纠错等级，见下 |
| `charset` | `UTF-8` | 非 null | 文本编码 |
| `foregroundColor` | `0xFF000000` | 任意 | 暗模块颜色，ARGB |
| `backgroundColor` | `0xFFFFFFFF` | 任意 | 亮模块颜色，ARGB，支持透明 |
| `centerText` | `null` | 非空白或 `null` | 中间提示文本，`null` 表示不叠加 |
| `centerTextFontName` | `Font.SANS_SERIF` | 非空白 | 字体名称，逻辑字体名或已安装的物理字体名 |
| `centerTextFontSize` | `0` | `0` 或 `[6, 512]` | 字号（像素），`0` 表示自动适配到能放入背板的最大字号 |
| `centerTextColor` | `0xFF000000` | 任意 | 提示文本颜色，ARGB |
| `centerTextBackgroundColor` | `0xFFFFFFFF` | 任意 | 提示文本背板颜色，ARGB；alpha 为 0 表示不铺背板，只画文字 |
| `centerTextAreaRatio` | `0.22` | `[0.05, 0.30]` | 背板边长占图片边长的比例 |

```java
QrCodeOptions options = QrCodeOptions.builder()
    .size(512)
    .margin(2)
    .errorCorrection(QrCodeErrorCorrection.HIGH)
    .foregroundColor(0xFF1F2937)
    .backgroundColor(0x00FFFFFF)   // 透明背景
    .build();
QrCodeUtils.writeToFile("https://example.com/order/A-01", Path.of("build/qr/A-01.png"), options);
```

纠错等级 `QrCodeErrorCorrection` 是工具自有枚举（`LOW`/`MEDIUM`/`QUARTILE`/`HIGH`，约可恢复 7%/15%/25%/30% 的码字），不暴露第三方库类型。

## 中间提示文本叠加

设置 `centerText` 即可在二维码正中央叠加一段文字，常用于标注“扫码报修”“设备编号”等提示。

```java
QrCodeOptions labeled = QrCodeOptions.builder()
    .size(400)
    .errorCorrection(QrCodeErrorCorrection.HIGH)   // 叠加提示文本时必须使用非 LOW 的纠错等级
    .centerText("扫码\n报修")                        // 用 \n 显式换行，居中绘制，不自动换行
    .centerTextAreaRatio(0.24)
    .centerTextColor(0xFFB91C1C)
    .build();
String result = QrCodeUtils.toBase64("https://example.com/repair/A-01", labeled);
```

要点：

- **不配置时行为不变**：`centerText` 为 `null`（默认）时输出与不具备该能力时完全一致。
- **先铺背板再画字**：文字笔画直接画在模块上会被解码器误认成模块；铺一块纯色背板，相当于让中心区域整体“缺失”一块，落在二维码纠错能力可恢复的范围内。背板颜色的 alpha 为 0 时不铺背板、只画文字，这种组合仅适合本身留白已经足够的场景。
- **背板对齐模块网格**：背板边长按 `centerTextAreaRatio` 算出理想值后，向外取整到整数个二维码模块，避免中心出现半个模块的残留色块。
- **禁止与 `LOW` 纠错等级同时使用**：`LOW` 只能恢复约 7% 的码字，默认背板占比已遮挡约 4.8% 的面积且集中在正中央，叠加后可靠性没有保障。构建选项时会直接抛出 `IllegalArgumentException`，不会静默升级等级。建议配合 `HIGH`（约 30% 恢复能力）使用；`centerTextAreaRatio` 的上限 0.30 也对应这个约束，占比越大越应该用越高的纠错等级。
- **字号自动适配**：`centerTextFontSize` 为默认值 `0` 时，从可用最大字号开始逐步缩小，取第一个能让全部行都放进背板的字号；文本按 `\n` 分行后整体居中绘制，不做自动换行。显式指定字号后不会被自动缩放，超出背板会直接抛出 `IllegalArgumentException`（不会输出文字溢出到模块区域的图片）。缩到最小字号 6px 仍放不下时同样抛出该异常，需要缩短文本或调大 `centerTextAreaRatio`。
- **依赖运行环境已安装的字体**：`centerTextFontName` 只能用运行环境已安装的物理字体名或 `Font.SANS_SERIF` 等逻辑字体名，工具不内嵌字体文件。绘制前会检测提示文本里是否存在当前字体无法显示的字符，存在则抛出 `QrCodeException`（错误类别 `FONT`），而不是输出一串缺字的“豆腐块”。最小化容器镜像常常没有安装中文字体，部署这类环境且需要中文提示文本时，需要自行安装字体或指定已安装的字体名。
- 只支持文本叠加，不支持 Logo/图片嵌入，也不支持圆角、渐变等美化效果。

## 异常处理

`QrCodeException` 继承 `RuntimeException`，通过 `getErrorType()` 区分失败类别，不建议解析异常消息文本。

| `QrCodeErrorType` | 含义 | 典型场景 |
| --- | --- | --- |
| `ENCODING` | 文本无法按所选纠错等级或字符集编码 | 文本长度超出二维码容量上限 |
| `FONT` | 中间提示文本存在当前字体无法显示的字符 | 部署环境缺少所需的 CJK 字体 |
| `DECODING` | 待解码字节不是可识别的图片，或图片中未找到可识别的 QR_CODE 二维码 | 传入非图片字节、传入不含二维码的图片 |
| `IO` | 读写目标文件或输出流时发生 I/O 错误 | 输出流中断、目标路径不可写、待解码文件不存在 |

参数非法（`text`/`file`/`output`/`options` 为 `null`、空字符串、选项越界等）抛出 `IllegalArgumentException`，消息为中文，不包含调用方传入的完整文本内容。

```java
try {
    String base64 = QrCodeUtils.toBase64(text, options);
} catch (IllegalArgumentException exception) {
    log.warn("二维码参数非法：{}", exception.getMessage());
} catch (QrCodeException exception) {
    switch (exception.getErrorType()) {
        case ENCODING -> log.warn("文本超出二维码容量：{}", exception.getMessage());
        case FONT -> log.warn("提示文本包含字体无法显示的字符：{}", exception.getMessage());
        case DECODING -> log.warn("图片无法识别为二维码：{}", exception.getMessage());
        case IO -> log.warn("二维码读写失败：{}", exception.getMessage());
    }
}
```

## 文件写出行为

`writeToFile` 会在目标文件所在目录先写一个临时文件，写完后移动覆盖目标文件（优先使用原子移动，文件系统不支持时退回普通移动覆盖）：

- 父目录不存在时自动创建。
- 目标路径已存在同名文件时直接覆盖。
- 任何失败路径都会清理临时文件，不会在目标位置留下无法解码的残缺 PNG。

## Web 接入要点

- 下载响应：把 `HttpServletResponse.getOutputStream()` 直接交给 `write` 方法，响应头设置：
  - `Content-Type: image/png`
  - `Content-Disposition` 中的文件名做 URL 编码（含中文时尤其需要）。
- 单次调用有独立资源上限（`size` 上界 4096），但并发调用的内存占用会叠加，服务层应自行控制生成并发数。

```java
@GetMapping("/api/v1/orders/{orderId}/qrcode")
public void exportQrCode(@PathVariable String orderId, HttpServletResponse response) throws IOException {
    response.setContentType("image/png");
    response.setHeader("Content-Disposition",
        "inline; filename*=UTF-8''" + URLEncoder.encode(orderId + ".png", StandardCharsets.UTF_8));
    String content = orderQueryService.buildQrCodeContent(orderId);
    QrCodeUtils.write(content, response.getOutputStream());
}
```

解码同理，上传的图片文件可直接把 `MultipartFile.getInputStream()` 交给 `decode(InputStream)`，工具不关闭该流：

```java
@PostMapping("/api/v1/qrcode/decode")
public Result<String> decodeQrCode(@RequestPart("file") MultipartFile file) throws IOException {
    try (InputStream input = file.getInputStream()) {
        return Result.success(QrCodeUtils.decode(input));
    }
}
```

生成参数的组装、业务查询等逻辑放在 Service 层，Controller 只做参数接收、调用与响应（本项目当前未引入 Spring Web 依赖，上述片段仅作接入参考）。
