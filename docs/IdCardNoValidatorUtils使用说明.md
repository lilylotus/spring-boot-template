# IdCardNoValidatorUtils 使用说明

`IdCardNoValidatorUtils` 位于 `org.example.simple.util`，是无状态的身份证号校验工具类：校验中国大陆 **18 位居民身份证号**（GB 11643-1999 现行标准）的格式与准确性。纯本地正则匹配、日期计算和校验码算法，不依赖外部数据源。

## 支持范围

只支持 18 位现行标准身份证号。**不支持** 1999 年前已废止的 15 位老身份证号格式——老格式出生年份只有 2 位、没有校验码，无法可靠校验"准确性"，且国家已不再签发；如需兼容历史数据，应自行先转换为 18 位（补年份前两位 `19` 并重新计算第 18 位校验码）再调用本工具。

## API 速查

| 场景 | 方法 |
| --- | --- |
| 校验身份证号是否准确 | `isValid(String idCardNo)` |

```java
import org.example.simple.util.IdCardNoValidatorUtils;

boolean ok = IdCardNoValidatorUtils.isValid("110101199001010015"); // true
boolean bad = IdCardNoValidatorUtils.isValid("110101199001010016"); // false，校验码不匹配
```

## 三层校验逻辑

`isValid` 依次执行三层校验，任意一层未通过即返回 `false`：

1. **结构格式（正则）**：6 位地区码（首位非 0）+ 4 位年份（`18xx`/`19xx`/`20xx`）+ 2 位月份（`01-12`）+ 2 位日期（`01-31`）+ 3 位顺序码 + 1 位校验位（数字或 `X`/`x`，大小写均可）。
2. **出生日期真实性**：正则只能排除格式明显不对的日期，无法识别"2 月 30 日""4 月 31 日"这类格式正确但实际不存在的日期，需要再用 `LocalDate.of(year, month, day)` 校验；同时要求出生年份不晚于当前年份（不接受"出生于未来"）。
3. **校验码正确性**：按 GB 11643 附录 B（等价于 `ISO 7064:1983.MOD 11-2`）算法，用前 17 位数字加权求和、对 11 取余后查表得到期望校验码，与第 18 位比较。

## 对非法输入返回 false，不抛异常

`isValid` 对任何不合法的输入（包括 `null`、空白字符串、长度或字符错误、日期不存在、校验码不匹配）统一返回 `false`，**不抛出异常**：

```java
IdCardNoValidatorUtils.isValid(null);        // false
IdCardNoValidatorUtils.isValid("");          // false
IdCardNoValidatorUtils.isValid("not-an-id"); // false
```

这与项目里 `IpRangeCheckUtils.isInRange` 对非法参数抛异常的做法不同——那里的 `ip` 通常是调用方已经从可信来源拿到的值，格式错误属于用法错误；而身份证号校验的典型场景是直接校验用户表单输入，格式错误正是该方法存在的意义所在，是预期的业务结果，不是调用错误。

## 非目标

- 不支持 15 位老身份证号格式。
- 不校验地区码（前 6 位）是否为《GB/T 2260》中真实存在的行政区划代码——该码表随行政区划调整频繁变化，维护码表超出本工具"格式与准确性校验"的职责范围；本工具只校验地区码为 6 位数字且首位非 0。
- 不提供从身份证号提取出生日期、性别、地区码等信息的方法；只回答"这个号码是否准确"这一个问题。
- 不做姓名与身份证号的实名核验（需要外部权威数据源）。

## 线程安全

本工具类无状态，所有方法均可被多线程并发调用。
